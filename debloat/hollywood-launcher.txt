# Phase B: hand Home to our launcher (apps/tv). Same TV as hollywood.txt.
#
# Apply ONLY after:
#   1. apps/tv is installed (tools/tv install -r app-release.apk) and was opened by hand at least once;
#   2. the screensaver points at our DreamService:
#      tools/tv shell settings put secure screensaver_components dev.cardozo.hollywood.launcher/.screensaver.ClockDream
#   3. somebody is at the TV with the remote.
#
# Optional, for the remote's dead app keys (Netflix, TCL Channel, films), after this list:
#   tools/tv shell settings put secure enabled_accessibility_services dev.cardozo.hollywood.launcher/.remote.RemoteKeysService
#   tools/tv shell settings put secure accessibility_enabled 1
# then learn and assign the keys from the settings page (http://192.168.0.4:8765).
#
# On G10, disabling launcherx alone is not enough: setupwraith's RecoveryActivity also answers HOME
# (priority 1, seen in baseline/2026-10-22/query-home.txt) and takes over with a blank screen.
# Both go together. setupwraith is the first-run wizard: re-enable it before any factory reset
# (restore does that).
#
# Risks already checked on this TV:
#   - Wi-Fi networks owned by setupwraith are deleted when it is disabled. Not an issue here: the TV
#     is wired and `dumpsys wifi` lists no saved networks.
#   - On Google's own Chromecast hardware, setupwraith holds the Cast credentials. We are disabling
#     Chromecast anyway (hollywood.txt), so it does not matter.
#
# Ground truth after applying: `tools/tv shell dumpsys activity activities | grep mFocusedApp` after
# pressing Home must name dev.cardozo.hollywood.launcher. If it does not, restore at once:
#   tools/debloat.sh restore debloat/hollywood-launcher.txt

com.google.android.apps.tv.launcherx   # stock Google TV home (~130 MB with its coreservices process)
com.google.android.tungsten.setupwraith
com.google.android.apps.tv.dreamx      # ambient screensaver (~100 MB); switch screensaver_components first
